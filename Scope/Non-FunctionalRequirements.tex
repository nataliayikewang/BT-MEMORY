\subsubsection{Non-Functional Requirements}
\label{sec:non-functional-requirements}

The subsequent requirements fall under the non-functional category.

\textbf{NFR1. The application must provide real-time updates on expense processing status.}

The UI must update the expenses dashboard in less than \textbf{1 second} when any expense status changes.

\textbf{NFR2. The application must offer a responsive and user-friendly UI.}

The UI must be \textbf{responsive}, adapting to any device or screen size \cite{responsive-ui}, and user-friendly, allowing new users to upload, review, and save an expense within \textbf{5 minutes}.

\textbf{NFR3. The application must ensure high performance and availability.}

Upon user login, the application should load the previously uploaded expenses within \textbf{3 seconds}. Other basic user interactions (e.g., saving expense information, deleting expenses) should be completed under \textbf{500ms}. Additionally, the application should be available \textbf{24 hours} a day, \textbf{365 days} a year.

\textbf{NFR4. The application must support scalability as the company grows.}

The application should support \textbf{20 receipt uploads} without overloading the server. 

\textbf{NFR5.  The application must guarantee compliance with GDPR.}

The application must store only relevant data and use an external cloud platform (this project will use Azure) that meets GDPR standards for data manipulation (Azure SQL Database) and user access (Microsoft Entra ID).

\textbf{NFR6. The application must enable a more efficient expense management process and a streamlined approval workflow.}

The application must optimize the expense workflow from the current 20 minutes to \textbf{5 minutes} for both employees and finance staff, achieving a \textbf{75\%} efficiency gain.

\textbf{NFR7. The application must facilitate integration of future AI models.}

The application must facilitate new AI models integrations by changing a single endpoint.

\textbf{NFR8. The project must support automated deployment and testing.}

The application must implement Continuous Integration (CI) and Continuous Deployment (CD) pipelines to follow DevOps principles. When a new implementation is pulled into the source code, pipelines enforce thorough testing of the updated version to prevent bugs while ensuring high-quality code and fast delivery.
