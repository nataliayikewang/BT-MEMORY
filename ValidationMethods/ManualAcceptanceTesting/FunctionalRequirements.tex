\subsubsection{Functional Requirements}

The Product Owner (PO) was responsible for verifying the defined functional requirements. A demo is shown for every new functionality during the iterative meetings with the PO, who then approves it or requests additional implementation before considering the task completed.

Additionally, manual acceptance testing is performed by executing the primary user workflows defined in the use case diagrams (Section \ref{sec:functional-areas}). This ensures that the application behaves as expected from an end-user's perspective. A summary table of the obtained results for each use case is provided.
